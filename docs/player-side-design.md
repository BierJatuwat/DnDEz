# AI DM Platform — Player-side design

เอกสารรวมการออกแบบฝั่งผู้เล่น (คู่กับ [`dm-side-design.md`](./dm-side-design.md))

> **สถานะ**: ออกแบบรอบแรกเสร็จ 2026-08-21 · ยังไม่เขียนโค้ด
> หลักการที่ล็อกไว้ทั้งหมดอยู่ใน [`PROJECT-CONTEXT.md`](./PROJECT-CONTEXT.md) §2

---

## 1. หลักการตั้งต้น

Player client คือ **"หน้าต่างเข้าสู่ game state เดียวกัน"** ไม่ใช่แอปแยก — ใช้ข้อมูลชุดเดียวกับ
DM console (Character, MapState, Session) ต่างกันแค่มุมมองและสิทธิ์

**Action ของผู้เล่นทุกอันไหลผ่าน rules engine และ approval gate เดิม** ไม่สร้างเส้นทางแก้ state
คู่ขนาน — action → `Message` (author_type = player) → orchestrator ตีความ → tool call →
กลายเป็น `Proposal` ถ้า subsystem นั้นตั้งเป็น suggest

---

## 2. Action input — hybrid

- **ปุ่มคำสั่งพื้นฐาน** (attack / move / interact ฯลฯ) — แม่นยำ ตีความไม่ผิด
- **ช่อง free text** — สำหรับ role-play action ที่ปุ่มไม่ครอบคลุม

ทั้งสองทางไปที่ orchestrator ทางเดียวกัน ไม่ต้องเพิ่ม data model ใหม่

---

## 3. Fog of war

- **คำนวณอัตโนมัติจาก token position** ไม่ให้ DM กำหนดมือ (สอดคล้องกับหลักการเดิมที่ fog เป็น
  deterministic ไม่ผ่าน AI)
- อิง**ความสามารถและสกิลของตัวละคร** เช่น darkvision, สกิลที่ขยายการมองเห็น
- **นับความสามารถของเพื่อนร่วมทีมด้วย** ไม่ใช่แค่ของตัวเอง
- **อัปเดต real-time แม้ไม่ใช่เทิร์นตัวเอง** — เพื่อนร่ายคาถา Light หรือจุดตะเกียงกลางเทิร์นคนอื่น
  ผู้เล่นทุกคนเห็นบริเวณนั้นทันที

---

## 4. Turn UI (§B)

- แสดง **action / bonus action / reaction / movement** ที่เหลือเป็นแถบชัดเจน
  — จุดที่แท็บเล็ตชนะกระดาษ เพราะคนลืมตลอดว่าใช้ bonus action ไปหรือยัง
- **Movement** แสดงเป็นระยะคงเหลือ (เช่น 30 ฟุต เดินไป 15 เหลือ 15) + วงรัศมีบนแผนที่
- **Reaction** ใช้แล้วเทาทันที

### Reaction prompt (เกิดนอกเทิร์นตัวเอง)

Opportunity attack / Shield / Counterspell เกิดกลางเทิร์นคนอื่น → เด้ง interrupt prompt

- ใช้ **timeout** ไม่หยุดรอไม่จำกัด
- **DM ตั้งเวลาได้เอง ดีฟอลต์ 30 วินาที**
- หมดเวลา = ถือว่าไม่ใช้ reaction แล้วเกมเดินต่อ (กัน pacing สะดุด โดยเฉพาะ in-person)

---

## 5. การทอยลูกเต๋า

ตั้งค่าระดับแคมเปญ **2 โหมด**:

| โหมด | อธิบาย |
|---|---|
| ระบบทอยให้ | rules engine ทอยเอง (ดีฟอลต์ โดยเฉพาะ online) |
| DM กรอกผลเต๋าจริง | ผู้เล่นทอยเต๋าจริงบนโต๊ะ **DM เป็นคนกรอกผลเข้าระบบ** ผู้เล่นกรอกเองไม่ได้ |

โหมดที่สองปิดช่องโกงสนิทเพราะ input มาจาก DM ที่เห็นเต๋าจริงบนโต๊ะเท่านั้น
**rules engine ยังเป็นคนคำนวณผลลัพธ์เหมือนเดิม** แค่รับตัวเลขดิบจากคนแทน RNG

> ⚠️ ข้อควรระวังที่รู้อยู่แล้ว: โหมด in-person ผู้เล่นหลายคนทอยรัว ๆ DM ต้องกรอกทุกครั้ง
> = ภาระ DM เพิ่ม ซึ่งสวนทางกับเป้าหมายลด workload — **ปล่อยไว้ก่อน รอ feedback จากการใช้จริง**
> ถ้าเป็นปัญหาจริงค่อยออกแบบ input ให้เร็วขึ้น (กดตัวเลขปุ่มเดียว ไม่ใช่กรอกฟอร์ม)

---

## 6. DM override — DM เล่นแทนตัวละครผู้เล่นได้

- **DM เข้าควบคุมตัวละครผู้เล่นได้ตลอดเวลา** ไม่จำกัดเฉพาะตอนผู้เล่นหลุด
  ไม่ต้องมี grace period หรือขอ consent ล่วงหน้า
- **ไม่ขัดกฎที่ล็อกไว้** เพราะกฎเดิมห้ามแค่ **AI** สั่ง action แทนตัวละครผู้เล่น ไม่ได้ห้ามคน
- แก้ปัญหาผู้เล่นเน็ตหลุดกลาง combat ในระบบที่เป็น online-only ไปในตัว
- **ต้องมี log บอกว่า action ไหนมาจาก DM ไม่ใช่จากผู้เล่นเอง** (กันงงตอนย้อนดูภายหลัง)

---

## 7. Panel แนะนำ action ("ตาฉันแล้ว ทำอะไรได้บ้าง")

แก้ปัญหาผู้เล่นมือใหม่นิ่งเงียบเพราะไม่รู้ว่าทำอะไรได้ — AI เสนอ**ตัวเลือก** ไม่เลือกแทน
(ไม่ขัดกฎตายตัว เพราะผู้เล่นยังเป็นคนตัดสินใจเอง)

- **จำกัดสิทธิ์**: ใช้ได้เฉพาะคนที่มี **API token ของตัวเอง** หรือ **DM แชร์ token ให้** — เพราะถ้าเปิดให้ทุกคน
  จะเปลือง token มาก
- **ผลลัพธ์ขึ้นบนจอ DM** ให้ **DM เป็นคนพูดแนะนำผู้เล่น** ไม่ขึ้นจอผู้เล่นโดยตรง
  (สอดคล้องกับหลักการ in-person ที่ DM เป็นคนเล่าเอง)
- เป็น **opt-in ต่อผู้เล่น** — มือเก๋าปิดได้ ไม่ต้องโดนป้อนตลอด

> ⏳ **ยังไม่ตัดสินใจ**: โหมด online ที่ DM ไม่ได้พูดสด (เล่นแบบพิมพ์) การขึ้นจอ DM อย่างเดียว
> อาจช้าไป — อาจต้องมีปุ่มให้ DM ส่งต่อให้ผู้เล่น **รอ feedback ก่อน**

## 8. Rest phase — 3 สถานะ

| สถานะ | เนื้อหา |
|---|---|
| หน้าจอพัก | เลือก hit dice / สกิลเฉพาะช่วงพัก (ตาม `PlayerRestAction` เดิม) |
| หน้าจอ role-play | ผู้เล่น role-play ระหว่างพักได้ |
| ดีดกลับ action ปกติ | เมื่อมี random encounter แทรก ต้องทอยเต๋าดำเนิน action ทันที |

### การ resolve เมื่อโดน encounter แทรกกลางคัน

- **Long rest**: คำนวณเป็น **%** จาก HP ที่ฟื้นไปแล้ว และเวลาที่พักไปแล้วเทียบกับเวลาที่ต้องการเต็ม
  (เช่น ต้องการ 8 ชม. โดนแทรกที่ 4 ชม. = 50% → คืน resource ตามสัดส่วน)
- **Short rest**: **ตัดสินล่วงหน้าตั้งแต่เริ่มพัก**ว่ารอบนี้จะมี encounter แทรกหรือไม่
  ไม่ใช้การคำนวณ % แบบ long rest

---

## 9. Death saves

- ตัวละครสลบ → จอเปลี่ยนเป็น **โหมด death save เต็มหน้า** ไม่ใช่ sheet ปกติที่กดอะไรไม่ได้
- แสดง **สำเร็จ ●●○ / ล้มเหลว ●○○** เป็นภาพ ไม่ใช่ตัวเลข
- ถึงตาตัวเอง → prompt ทอย death save ผ่านช่องทางเดียวกับ §5 (ระบบทอย หรือ DM กรอกผลเต๋าจริง)
- กติกาตาม SRD: สำเร็จ 3 = stable, ล้มเหลว 3 = ตาย, nat 20 = ฟื้น 1 HP ทันที, nat 1 = นับล้มเหลว 2,
  โดนโจมตีตอนสลบ = ล้มเหลว 1 (crit = 2)
- สถานะ **stable** แสดงแยกชัดจาก "กำลังทอยอยู่"
- **ตอนสลบยังไม่ถูกตัดขาดจากเกม** — ใช้ช่องทางลับ (§10) และช่อง role-play ได้อยู่
  (เช่นบรรยายภาพนิมิตตอนใกล้ตาย) ไม่ให้คนนั้นนั่งเฉย ๆ 3 เทิร์น
- **เพื่อนเห็น**: สถานะล้ม/stable เสมอ ส่วนจำนวนสำเร็จ-ล้มเหลว **เห็นโดยดีฟอลต์**
  (เป็นแรงกดดันที่ทำให้เกมสนุก) แต่ DM ปิดได้ถ้าอยากเล่นแบบลุ้นมืด

---

## 10. ช่องทางลับ DM ↔ ผู้เล่นคนเดียว

ใช้ทั้งสองทิศ:
- **ผู้เล่น → DM**: ประกาศ action ลับ (แอบไปสอดแนมคนเดียว)
- **DM → ผู้เล่นคนเดียว**: ผลทอย Perception ที่คนอื่นไม่ควรรู้, ข้อมูลที่ตัวละครโดนหลอกให้เชื่อ

ใช้กฎการมองเห็นเดียวกับ `secrets[]` ที่มีอยู่แล้ว

---

## 11. Character sheet — แก้อะไรได้บ้าง (§A)

**rules engine เป็นเจ้าของตัวเลขกลไกทั้งหมด** ผู้เล่นแก้ HP / resource / XP ตรง ๆ ไม่ได้
เปลี่ยนได้ผ่าน tool call เท่านั้น

| แก้เองได้ | แก้เองไม่ได้ |
|---|---|
| โน้ตส่วนตัว, คำบรรยาย/รูปตัวละคร | HP, resource, XP, ตัวเลขกลไกทุกชนิด |
| จัดเรียง inventory | ไอเทมที่มี/ไม่มี |
| เตรียม spell (เฉพาะช่วงที่กติกาอนุญาต เช่นตอนพัก) | spell slot ที่ใช้ไปแล้ว |

ถ้าตัวเลขผิดพลาดจริง → ปุ่ม **"ขอให้ DM แก้"** ส่งเป็น request ไม่ใช่แก้เอง

---

## 12. Party view (§C)

- เห็น **HP เพื่อนเป็นตัวเลขจริง** ไม่ใช่แค่แถบ — คนเล่น healer ต้องคำนวณว่าเยียวยาเท่าไหร่ถึงคุ้ม
- เห็น condition ของเพื่อน + ใครสลบ (ต่อกับ §9)
- **ไม่เห็น HP ศัตรู** (กฎเดียวกับ table view ฝั่ง DM)

---

## 13. Condition tooltip (§D)

มือใหม่โดน Poisoned แล้วไม่รู้ว่าแปลว่าอะไร → แตะที่ condition แล้วอธิบายได้ทันที

**ดึงจาก `RulesCorpus` (SRD 5.2) ที่ฝังไว้ในระบบอยู่แล้ว — ไม่เรียก AI = ไม่เปลือง token**

---

## 14. Personal log (§E)

- log เฉพาะสิ่งที่**ตัวละครตัวเองรับรู้จริง** ไม่ใช่ log รวมที่มี secret ของ DM
  (ใช้กฎเดียวกับ Player-version ของ `RecapSnapshot`)
- ผู้เล่น **จดโน้ต / ปักหมุดเองได้** ในนี้ (เช่น "Garrick โกหกเรื่องกุญแจ")
  — คนเล่น D&D จดกันอยู่แล้ว ถ้าไม่มีที่จดจะไปเปิดแอปอื่นแทน

---

## 15. Pending proposal

**ผู้เล่นไม่เห็นคิว proposal ที่ DM กำลังตัดสินใจ** ไม่มีแม้แต่สถานะ "DM กำลังพิจารณา"
เพื่อไม่ทำลาย pacing และตรงกับหลักการเดิมที่ proposal เป็นของ DM เท่านั้น

---

## 16. Notification

**ไม่ทำกฎ "จอเงียบโดยดีฟอลต์" ในโหมด in-person** — ปล่อยให้แจ้งเตือนตามปกติ

## 17. Join flow

แบบเดียวกับ Discord — **หน้า join เดียว ทางแยกอยู่ตรงนั้น**

```
DM สร้าง session → แชร์ QR หรือ URL (เลือกได้)
   ↓
ผู้เล่นเปิดลิงก์ → เลือก [ Login ]  หรือ  [ Quick play (ใส่แค่ชื่อ) ]
```

- โหมด in-person: โชว์ **QR บน table view** เดินมาถึงโต๊ะสแกนเข้าได้เลย
- มี **รหัสสั้น 6 หลัก** สำรองไว้เผื่อกล้องมีปัญหา (พิมพ์เร็วกว่า URL ยาว)

## 18. คลัง character preset

**เป็นระบบหลักของแพลตฟอร์ม ไม่ใช่แค่ของ quick play** — 4 ทางเลือกในการมีตัวละคร:

| ทาง | อธิบาย |
|---|---|
| ใช้ preset ตามที่เป็น | เลือกจากคลังแล้วเล่นได้เลย (เร็วสุด) |
| preset + ปรับแต่ง | เลือกเป็นฐานแล้วแก้ตามต้องการ |
| สร้างเองตั้งแต่ต้น | builder เต็มรูปแบบ |
| นำเข้า | เอาตัวละครจากแคมเปญอื่นมาใช้ |

- **preset ที่ถูกแก้แล้วต้องผ่าน validation ของ rules engine** (point buy ถูกกติกาไหม,
  จำนวน spell ถูกไหม) ไม่ผ่าน → ติด flag ให้ DM เห็นในคิว review — ใช้ rules engine ไม่พึ่ง AI
- **DM สร้าง preset ของแคมเปญตัวเองได้** ใช้โครงเดียวกับคลังกลาง

### Level เริ่มต้น

- **DM กรอกเป็นตัวเลขได้อิสระ** ว่าเริ่ม level ไหน
- preset ต้อง **auto-level แบบ deterministic** — กำหนดเส้นทางมาตรฐานไว้ในแต่ละ preset
  ว่า level ไหนได้ feat/ASI/spell อะไร ระบบเลื่อนให้เอง ผู้เล่นเข้าไปปรับทีหลังได้
- เป็นโค้ดปกติ ตรงกับหลักการที่ rules engine เป็นเจ้าของกติกา **ไม่ใช้ AI สร้าง build**
  (อันนั้น parked ไว้ phase หลัง)

## 19. Harvest — คลัง preset ที่โตขึ้นเองตามการใช้งาน

ตัวละคร quick play ที่ถูกทิ้ง และตัวละครที่เคยไต่ถึง level นั้น ๆ **เก็บมาเป็น preset**
→ ยิ่งระบบดำเนินไป pool ยิ่งรวย และเป็น build ที่ผ่านการเล่นจริง ไม่ใช่ build ที่นั่งเดา

**ยังต้องมี auto-level (§18) อยู่** เพราะช่วงแรกคลังยังว่าง (cold start) และ level ที่ยังไม่มีใคร
เล่นถึงก็ยังไม่มีของ — สองอย่างเสริมกัน ไม่ได้แทนกัน

### กติกาการ harvest (บังคับทั้ง 4 ข้อ)

1. **ต้องมี consent** — ตอนจบ session เพิ่มตัวเลือก
   *"ไม่เก็บตัวละครนี้ แต่อนุญาตให้ระบบนำโครงสร้างการสร้างไปใช้เป็นแม่แบบให้คนอื่นได้"*
   ไม่ติ๊ก = **hard delete ตามเดิม** (ดู PROJECT-CONTEXT §2 — ข้อนี้แก้กฎเดิม)
2. **เก็บเฉพาะ "โครง" ไม่ใช่ "ตัวละคร"** — ตัดชื่อ, backstory, รูป portrait, โน้ตส่วนตัวทิ้ง
   เก็บแค่ race / class / subclass / level / ability score / feat / spell / equipment
   → กลายเป็น **build template** ไม่ใช่ตัวละครของใคร
3. **ห้ามให้เนื้อหาจาก source import หลุด** ⚠️ สำคัญที่สุด — ถ้าตัวละครถือไอเทมหรือใช้ feat
   ที่มาจาก `SourceDocument` ที่ DM สแกนเข้ามา **แม้ชิ้นเดียว** → เข้าคลังกลางไม่ได้
   ไปได้แค่คลัง preset ส่วนตัวของ DM คนนั้น (กฎ private ต่อแคมเปญที่ล็อกไว้)
   **harvest เข้าคลังกลางได้เฉพาะตัวละครที่อ้างอิง SRD ล้วน ๆ**
4. **กันคลังบวมและของเสีย** — เก็บเฉพาะตัวละครที่เล่นจริงพอสมควร (ผ่าน session จบจริง
   ไม่ใช่กด join แล้วหายไปใน 5 นาที), ต้องผ่าน validation ของ rules engine,
   **dedupe ด้วย build fingerprint** แล้วนับ popularity แทน
   (ของแถม: รู้ว่า build ไหนคนนิยม เอาไปเรียงลำดับในคลังได้)

## 20. Companion mode — นำเข้า sheet กระดาษ

โหมดนี้ผู้เล่นใช้กระดาษ แต่ระบบยัง track resource ให้ → ถ้าให้ DM กรอก sheet แทนทุกคนจะช้ามาก
และสวนทางกับเป้าหมายลดภาระ DM

**ถ่ายรูป character sheet กระดาษ → vision extraction → DM review → เข้าระบบ**

ใช้ **pipeline เดียวกับ source import ที่ออกแบบไว้แล้ว** (extract → review → commit)
ไม่ต้องสร้างระบบใหม่ แค่เพิ่ม output type เป็น `CharacterSheet`

## 23. สิ่งที่ต้องเพิ่มใน data model

> ยังไม่ใช่ schema สุดท้าย — เป็นรายการที่ตามมาจากการตัดสินใจในเอกสารนี้

```
CharacterPreset (scope: global/campaign, source: authored/harvested,
                 build_fingerprint, popularity_count, srd_only bool,
                 level_path jsonb  ← เส้นทาง auto-level)
PrivateMessage (session_id, from_user_id, to_user_id, content)   ← §10
DeathSaveState (character_id, successes, failures, status)       ← §9
CharacterReview (character_id, status, flagged_reasons[])        ← §21

Campaign settings เพิ่ม:
  dice_mode: system_roll | dm_enter                    ← §5
  reaction_timeout_seconds (default 30)                ← §4
  character_review_required bool                       ← §21
  death_save_visibility: party_visible | dm_only       ← §9
  starting_level int                                   ← §18

Character เพิ่ม:
  controlled_by_dm bool / action log source field      ← §6
  harvest_consent bool                                 ← §19

SourceDocument output type เพิ่ม: CharacterSheet        ← §20
```
