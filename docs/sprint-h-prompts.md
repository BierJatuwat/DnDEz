# Sprint H — งานที่เหลือก่อน playtest กับคนจริง

เป้าหมายของ sprint นี้: **พา DM กับผู้เล่นจริงนั่งลงเล่นได้ตั้งแต่ศูนย์** โดยไม่ต้องมีใคร insert SQL ให้

สถานะตั้งต้น (หลัง Sprint G ครบ 10 Part, commit `83552fa`): กฎการต่อสู้/การเคลื่อนที่/OA/affordance
ทำงานครบและมีเทสต์คุม แต่ **ทุกฉากที่เคยทดสอบมาถูก seed ด้วย SQL ทั้งหมด** ยังไม่เคยมีใครสร้าง
แคมเปญ→อัปโหลดแผนที่→วาง token ด้วยมือจริงสักครั้ง

---

## ⚠️ อ่านก่อนสั่งงาน — ข้อมูลจริงจาก Sprint G เรื่องการใช้ `<tier>`

Sprint G dispatch subagent ไป **16 ครั้ง ชนเพดาน turn 8 ครั้ง** (ดู `.claude/logs/routing.md`)
รูปแบบที่ **สำเร็จ** มีลักษณะเดียวกันหมด:

> **ไฟล์เดียว · pure logic · ระบุ API surface ครบทุกตัวในพรอมต์ · มีเทสต์ red รออยู่แล้ว**

รูปแบบที่ **ล้มเหลวเกือบทุกครั้ง**: งาน integration หลายไฟล์ (endpoint + store + hub + DI),
งาน security review, และงานที่ agent ต้องไปสำรวจโครงสร้างเองก่อน

**ข้อเสนอ**: ใช้ `<tier>` เฉพาะ Part ที่มีแกน pure แยกออกมาได้ชัด แล้ว dispatch **เฉพาะแกนนั้น**
ส่วน integration ให้ owner ทำเอง · Part ที่เป็น UI ล้วนอย่าใช้ tier เลยตามกฎเดิมใน CLAUDE.md

- `SceneMap` รับ prop `pixelsPerSquare` อยู่แล้ว และมี `cellToPx` เป็นจุดแปลงหน่วยจุดเดียว

## สิ่งที่ต้องทำ
1. เขียนตัวแกะ `scenes.grid` ฝั่ง frontend (ไฟล์ใหม่ใน `lib/` + เทสต์) — parse แบบไม่ไว้ใจข้อมูล
   เลย: grid เป็น `'{}'` ได้ (ฉากที่ DM ยังไม่ตั้งกริด), เป็น JSON พังได้, ฟิลด์หายได้
   ทุกกรณีต้องคืนดีฟอลต์ ไม่ใช่ throw
2. ส่ง `pixelsPerSquare` ที่แกะได้เข้า `SceneMap` ทุก call site (PlayerView, DmConsole, TableView)
3. `offsetX`/`offsetY` — ถ้ายังไม่ได้ใช้ในการวาด ให้แกะเก็บไว้แต่เขียน comment กำกับว่ายังไม่ได้

## ⚠️ สองเส้นทางที่ต้องแยกให้ชัดใน UI
มีสองความหมายที่ต่างกันจริง อย่ายุบรวมกัน:
- **วาง/ย้ายอิสระ** (PATCH token) — DM จัดฉาก ย้ายอะไรไปไหนก็ได้ ไม่คิดระยะ ไม่เกิด OA
  ใช้ตอนเซ็ตอัพก่อนเริ่ม หรือตอนเล่าเรื่อง
- **เดินตามกฎ** (movement/commit) — หัก speed จริง เกิด OA จริง ใช้ตอน NPC เดินในการต่อสู้
DM ต้องเลือกได้ว่ากำลังทำอันไหน และ UI ต้องบอกชัดว่าตอนนี้อยู่โหมดไหน — ไม่ใช่เดาให้

## สิ่งที่ต้องทำ
1. วาง token ใหม่: เลือก entity (ตัวละคร/NPC ที่มีในแคมเปญ) → คลิกช่องบนแผนที่ → เกิด token
2. ขยับ token: ลากได้ทุกตัวในโหมด "จัดฉาก" · ในโหมด "เดินตามกฎ" ลากได้เฉพาะตัวที่ ControlledByDm
   และต้องเห็นขอบเขต reachable เหมือนฝั่งผู้เล่น
3. ลบ token
4. สลับโหมดให้ชัดเจนบนหน้าจอ

## ห้ามทำ
- ห้ามแก้ endpoint ฝั่ง .NET (มีครบแล้วทั้ง POST/PATCH/DELETE/commit/reachable)
- ห้ามแตะ TableView (จอกลางต้องไม่มี input ตามที่ล็อกไว้ Part 6)

## ทำไมต้องมี Part นี้
ทุกฉากที่เคยทดสอบใน Sprint G **ถูก seed ด้วย SQL ทั้งหมด** (แคมเปญ/เซสชัน/ฉาก/หมอก/token/preset)
เราจึงยังไม่รู้เลยว่าเส้นทางที่ผู้ใช้จริงต้องเดินนั้นใช้ได้ไหม — ของที่เทสต์ผ่านหมดกับข้อมูลที่เรา
ป้อนเอง อาจพังตั้งแต่ขั้นแรกกับข้อมูลที่ผู้ใช้สร้างเอง

## สิ่งที่ต้องทำ
เปิดเบราว์เซอร์แล้วเดินให้ครบเส้นทางนี้ **โดยห้ามแตะ psql/SQL แม้แต่คำสั่งเดียว**:
1. สมัครบัญชีใหม่ (DM) → สร้างแคมเปญ
2. สมัครบัญชีที่สอง (ผู้เล่น) → เข้าร่วมด้วย join code
3. DM เปิดเซสชัน → อัปโหลดแผนที่จริงสักใบ → ตั้งกริดให้ตรงตาราง
4. ผู้เล่นสร้างตัวละครจาก preset
5. DM วาง token ของผู้เล่นและของมอนสเตอร์ลงแผนที่
6. DM เปิดหมอกบางส่วน → เปิด encounter
7. ผู้เล่นเดิน/โจมตี · DM ตอบ OA
8. เปิดจอกลาง (/table) ดูว่าแสดงถูกไหม

**ทุกจุดที่สะดุด ให้แก้** และบันทึกไว้ว่าสะดุดตรงไหนเพราะอะไร

## สิ่งที่คาดว่าจะเจอ (จากที่รู้ตอนนี้ — ยังไม่ยืนยัน)
- อัปโหลดแผนที่แล้วตั้งกริดอาจไม่มี UI ที่ใช้งานได้จริง (มีแต่ endpoint)
- ตัวเลข x/y ตอนวาง token ครั้งแรกอาจไม่ตรงกับตารางบนรูป
- ผู้เล่นที่ยังไม่มี token บนแผนที่จะเห็นอะไรบ้าง — เส้นทางนี้ยังไม่เคยทดสอบ

## ห้ามทำ
- ห้าม seed ข้อมูลด้วย SQL เพื่อข้ามขั้นตอนที่พัง — ถ้าพังคือต้องแก้ ไม่ใช่ข้าม
- ห้ามแก้เทสต์เดิมให้ผ่าน

## ปัญหาที่จะแก้
`MovementCostResolver` ของ Part 8 รองรับพื้นเดินยากและกำแพงครบแล้ว **แต่ไม่มีข้อมูลป้อนให้เลย** —

MovementCommitEndpoints) ผู้เล่นจึงเดินตรงได้เสมอ ไม่มีอะไรให้อ้อม และ Dijkstra ที่เขียนไว้ก็ไม่เคย
ได้ทำงานจริง

## ข้อเท็จจริงที่ตรวจแล้ว
- `scenes.grid` เก็บแค่ `{pixelsPerSquare, offsetX, offsetY}` — ไม่มีรายการช่องใด ๆ
- `Scene` entity ไม่มีฟิลด์เกี่ยวกับพื้น/กำแพงเลย
- `TerrainField` (Part 8) แยก `FromMap` กับ `FromEffects` ไว้แล้วโดยตั้งใจ — §3.3 บอกว่าต้องแยก
  เพราะพื้นจาก effect (Web/Grease) ต้องลบทิ้งทั้งชั้นได้ตอนเวทหมดเวลา โดยแผนที่ไม่สกปรกถาวร
- `TerrainField` รวมสองชั้นด้วย **OR ไม่ใช่คูณ** (SRD: "Difficult Terrain isn't cumulative")

## สิ่งที่ต้องทำ
1. ที่เก็บพื้นจากแผนที่ (ผูกกับ scene) — ตัดสินใจว่าจะเป็นคอลัมน์ jsonb ใหม่ หรือขยาย `grid`
   แล้วเขียนเหตุผลกำกับ · **ถ้าสร้างตารางใหม่ ต้องเปิด RLS เองในไฟล์ migration นั้น**
   (กฎถาวรใน CLAUDE.md — ตารางใหม่ fail open ถ้าลืม)
2. Endpoint ให้ DM ทำเครื่องหมาย/ลบ ช่องพื้นเดินยาก และช่องกำแพง (DM-only)
3. ต่อเข้า `MovementPreviewEndpoints` / `MovementCommitEndpoints` แทน `TerrainField.Empty`
4. ที่เก็บพื้นจาก effect (ผูกกับ encounter) — ถ้าประเมินว่าใหญ่เกิน ให้ทำแค่ชั้นแผนที่ก่อน
   แล้ว**เขียนกำกับชัด ๆ ว่าชั้น effect ยังไม่ทำ** อย่าปล่อยเงียบ

## security — ต้อง dispatch security-reviewer
